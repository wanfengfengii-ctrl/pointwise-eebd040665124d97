# 潮影巡回动画展放映工作台

编排、发行和交班使用中央工作台。东馆和西馆各有本地工作台及独立 SQLite 库。馆员在中央停用期间也可以从已安装的节目办理试映、开映、结束和封报。工作台仅监听本机回环地址，使用 Python 3.11 标准库，无需安装依赖。

```sh
python3 -B -m desk.app --role central --db central.sqlite --port 8000
python3 -B -m desk.app --role east --db east.sqlite --port 8001
python3 -B -m desk.app --role west --db west.sqlite --port 8002
```

分别在终端运行以上三条命令，然后在浏览器打开 `http://127.0.0.1:8000`、`:8001` 和 `:8002`。重启沿用原数据库，保留草稿修改、正式发行、开馆、现场活动及班报。馆库初始化时绑定馆身份。

## 一天的办理顺序

1. 在中央「编排」粘贴 `samples/lanterns.json` 的有序分镜清单并保存。可以按原草稿号再次编辑。
2. 在 999、1000 和 1500 毫秒分别校样，确认首段、次段和结束，然后冻结。保留固定节目号，原号可以查询节目时间表及任一合法时点。
3. 从「发行」选择固定节目，为展次 `tide-day` 填东馆 3 次、西馆 1 次，下载两份馆件。
4. 在两个馆端分别上传本馆馆件，选择 `tide-day` 并试映 1000 毫秒。试映记录进入班报，余额仍为 3 和 1。
5. 两馆分别填开映申请号并开映。开映结果页给出原场次号和节目时点入口。东馆结束其场次，西馆保留待结束场次。若开映失答，请以原申请号办理。
6. 两馆分别按实际开映所在的营业日期、班别封报并下载。馆端待结束清单也显示属于前班的未结束场次。
7. 在中央「交班」上传两份班报，选择其接纳编号并核对。查看两馆节目号、试映数、正式开映数、已结束数和待结束数。

## 业务口径及接口

节目清单是 JSON 数组，每项恰有 `title`、`body` 和 `duration_ms`，正文与次序原样保留。时长须为正整数，时间点为非负整数毫秒，累计分段左闭右开，总终点显示结束。分额是非负整数，含零。JSON 小数和布尔值属于非法时长。展次号、申请号及其他业务编号使用 1 至 64 个 ASCII 字母、数字、点、下划线或连字符，首字符须为字母或数字。业务错误页面保留办理入口，非法件或参数用 422，找不到记录用 404，异参冲突和余额不足用 409，数据库未能完成操作用 503。

中央页面从 `/draft`、`/proof`、`/program`、`/issue` 和 `/intake` 进入。馆端从 `/venue`、`/screening` 和 `/shift` 进入。编辑、安装、试映、开映、结束、封报、接纳和核对使用页面中的 POST 表单。馆件和报告通过页面的下载链接及文件上传交接。V1 的 JSON 文件按原样传送，封装包含用途、版本与内容校验摘要，供受信任工作人员检查传输损坏。馆件包含固定节目快照及单馆分额，班报包含固定节目号、班次、计数及正式场次明细。

同展次同参可重领两份原馆件，同展次异参拒绝。重装原馆件保留当地历史。开映以当地展次和申请号取得原场次，余额同时反映本馆已成功办理的全部开映。用尽后仍可复领旧场次。结束保留首次结束时点，不返还分额。营业时间为 UTC+08:00，AM 和 PM 分别覆盖当日 `[00:00,12:00)` 和 `[12:00,次日00:00)`。开映按开始时点归班，封报固定办理时可见的结束状态。已知展次可封空班班报。一次封报可以原件重领，随后发生的活动继续反映在现场记录。中央可重复接纳原班报。核对要求同展次异馆，双方各自的班次和节目号均在结果页列出。

Python 入口按职责组织。`program.draft` 和 `program.edition` 提供保存、查询和冻结，`program.timing` 提供统一定位，`tour.issue` 提供发行和馆件下载。`venue.local_store.open_venue_store` 打开绑定馆库，`venue.install`、`venue.rehearsal`、`venue.screening`、`venue.close` 和 `venue.activity` 分别提供安装、试映、开映、结束和现场读取。`report.shift`、`report.intake`、`report.reconcile` 分别提供封报、接纳和核对。`desk.app.create_server` 接受角色、路径、端口及可选馆钟，接线和初始化均与命令行入口一致。现场 API 的 `now` 和馆钟返回 Unix 整数秒，默认使用系统时间。直接调用者可用 `core.connect` 配合各领域 `initialize_*` 建立所需表。领域错误公开 `core.BusinessError.code` 和 `status`。

## 校正版换版交接

中央为已发行展次选择一个不同的固定节目，登记一次换版计划。中央能看出两馆各自的停旧凭据是否已到，馆端能看出当前可首开的节目或等待的材料。交接沿用受信任工作人员下载、原样转送及上传文件的流程。

每馆的停旧实据须对应同一计划并以该馆已持久停止旧版首次开映为依据。两馆实据齐备后中央才可发出可复领的授权，两馆可各自离线启用。同一馆只有在能读取与授权相符的完整新版后才可首次开映新版。等待授权或新版材料时，已经停旧的馆继续停旧。停旧与本馆首次开映按实际生效的先后裁决，成功交出的凭据在重开后可复领。损坏文件、其他计划或展次的文件、错馆的馆别专用文件均不推进办理。重送同一馆的原凭据仍只算该馆一次，重领授权或重送有效原件不再生效一次。

原开映申请照常复领原场次。旧开映表单提交未办申请时，已停旧的馆不得开出旧场，已启用新版的馆也不得按该表单开出新场。刷新后可按当地已启用的节目提交新申请。旧场仍可按开映号查看开场时的分镜并办理结束。始终按展次累计分额，首发开馆件及其重装行为照常。班报继续按展次和原班次口径计数，报头的节目号仍指首发节目，已封报告按原件复领。

### 一次交接样例

为 `tide-switch` 冻结 `samples/lanterns.json` 作为原版，再将下列分镜另存并冻结为校正版。分别安装东馆 3 次、西馆 2 次的原开馆件。东馆以申请 `A` 开映，留一张旧开映表单。东馆先停旧，余额仍为 2。西馆的凭据未到时，中央尚不能发授权，尚未停旧的西馆可以照常开一次旧版。西馆停旧、两馆实据齐备后，领取授权并关闭中央。把有效材料先送东馆，东馆可启用新版，尚未启用的西馆即使余 1 次也仍须等待。再给西馆送齐合格材料，西馆可以用余下次数开新版。

东馆启用后从旧表单提交 `A` 应复领原场次，用这张表单提交未办申请应被拒。刷新后可新开 `B`，东馆余 1 次。重开东馆工作台并分别查询两个开映号，在 1000 毫秒处，`A` 须显示原版第 2 段，`B` 须显示校正版第 1 段「潮门（校正）」。仍可结束 `A`。若 `A`、`B` 在同一班内开映且该班尚未封报，东馆该班正式开映数为 2，报头显示首发节目号，重复封报领取同一原件。

```json
[
  {"title": "潮门（校正）", "body": "门灯先亮，纸船再过桥。", "duration_ms": 1200},
  {"title": "回港（校正）", "body": "纸船沿右岸回到灯下。", "duration_ms": 500}
]
```

在原回归之外，从本地 HTTP 表单重跑这条换版链路，并检查错件、重送和重开边界。`.pointwise-runtime.json` 沿用版本 1 的 `cli` 清单来启动多工作台场景，`setup` 列准备命令的参数数组，可为空。让 `verify` 与 `demo` 分别调用真实核验和换版演示的参数数组。核验保留原回归并在业务断言失败时返回非零，演示展示从工作台取得的开映与分镜结果。
